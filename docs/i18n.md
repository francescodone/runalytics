# Application Localization

The production React interface uses i18next with one UTF-8 JSON catalog per
language in `src/desk/locales/`: English (`en`), Spanish (`es`), French (`fr`),
German (`de`), Italian (`it`), Portuguese (`pt`), Japanese (`ja`) and Simplified
Chinese (`zh`). Initial translations are machine-generated and should receive
native-speaker review, especially training and medical terminology.

Settings > Appearance > Language lets each device choose a language or use the
system default. The choice is stored locally on that device and changing it
reloads the current page. The default uses the system's primary language
(`navigator.language` in the browser or native WebView). Regional tags such as
`es-MX` and `pt-BR` use the corresponding base language; unsupported languages
use English. Locale selection happens before the first React render, sets the
document language, and does not send data to a translation service. Catalogs
are bundled and work offline.

## Editing Copy

Use `t("English source text")` for interface copy. Keep a complete sentence in
one entry, including interpolation values such as `{{value0}}`, rather than
concatenating translated words. Existing shell keys retain their original
semantic names. Add or update the same key in all eight JSON files. Do not
translate route IDs, option values, provider codes, API field names, or units
used in calculations.

`text()` localizes known first-party generated display text using catalog
templates. Unknown messages are preserved instead of hiding diagnostic detail.
User notes, custom plan names, assistant replies, credentials, URLs and external
provider data remain unchanged. Translation never rewrites stored plans or IPC
payloads. The exported calendar and provider-side descriptions retain their
original language.

The locale-aware date and number helpers live beside the translation runtime.
Date-only values are parsed at local noon to avoid timezone-related day shifts;
date inputs and IPC continue to use ISO dates. English retains the existing
British date format. Workout pace values keep the standard minutes:seconds
notation and metric units.

## Verification

Run `node scripts/check-i18n.mjs` to check catalog parity, nonempty values,
interpolation integrity and static source keys. Run `npm run build` and
`npm run test:i18n` for compilation and synthetic-IPC browser
coverage. Existing English workflows remain part of the regression suite.

Browser locale emulation is not native-device validation. macOS and iPhone
WebView locale behavior and native-language proofreading require separate
acceptance checks.
